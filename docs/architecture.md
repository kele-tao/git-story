# Architecture

git-story is a pipeline of pure functions. Git is the only I/O; everything
after the parse is data in, data out, which is what makes the tests fast and the
output deterministic.

```
git binary
   |
   |  git log --pretty=format (0x1F separated)   git log --numstat -M
   v
+----------------+       +---------------------+
| _parse_metadata|       | _parse_numstat      |
+--------+-------+       +----------+----------+
         |                          |
         v                          v
    +-------------------------------------+
    | History  (commits, tags, path_map)  |
    +----------------+--------------------+
                     |
   +-----------------+------------------+------------------+
   v                 v                  v                  v
 metrics.py      onboard.py          html.py           reports.py
 bus factor      import graph        inline SVG        terminal tables
 hotspots        (ast.parse)         story page        chronicle / summary
 co-change       scoring
   |                 |                  |                  |
   +-----------------+------------------+------------------+
                     |
                     v
                 cli.py  ->  exit codes 0 / 1 / 2
```

## Module responsibilities

| Module | Responsibility | Pure? |
| --- | --- | --- |
| `gitio.py` | Discover the repository, run git safely, friendly errors | no (subprocess) |
| `history.py` | Parse commits, numstat, renames, tags; canonicalise paths | parse only |
| `classify.py` | Theme of a commit from message and diff shape | yes |
| `imports.py` | Real Python import graph via `ast`, conservative JS regex | yes |
| `metrics.py` | Bus factor, hotspots, co-change, monthly churn, findings | yes |
| `onboard.py` | Rank the files a newcomer should read | yes |
| `reports.py` | Terminal tables, colour, chronicle, summary | yes |
| `html.py` | Self-contained story page with inline SVG | yes |
| `cli.py` | Argument parsing, exit codes, JSON payloads | no |

## Why paths are canonicalised

`git log --numstat -M` reports a rename as `old => new`. Left alone, every
analysis would treat the old path as a live file: the bus-factor table grows a
phantom directory named `support}` and co-change finds pairs that no longer
exist. `History` therefore builds a rename map (following chains) and rewrites
every historical `FileChange` to the newest name. Churn is preserved; identity
is unified.

## Why the classifier is ordered message -> shape -> keywords

Teams either use Conventional Commits or they do not. If they do, the prefix is
ground truth and wins. If they do not, the diff is better evidence than the
words ("move x to y" is a refactor even without a prefix). Keyword matching is
the last resort and is deliberately narrow, because a wrong classification is
worse than an "other" bucket.

## Determinism

* No randomness anywhere in the analyses.
* Commits are sorted by `(timestamp, sha)`; equal timestamps cannot reorder.
* Every dict that reaches the output is explicitly sorted.
* The HTML page has no clock, no random id and no external asset.

Running the same command twice on the same repository produces byte-identical
output; `tests/test_cli.py` asserts the JSON shape, and the demo repository is
regenerated by a seeded script.
